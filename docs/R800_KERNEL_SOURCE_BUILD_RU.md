# SM-R800 — проверка исходников и изолированная пробная сборка ядра

**Репозиторий разработки:** только `vorlocsev/galwear`.
**Ветка:** `development/r800-kernel-source-ci-20261124`.
Никаких PR, записей в `main`, изменений исходного проекта Depth118, прошивки часов или публикации готового firmware.

## Подтверждённая база ядра

Используем точный коммит:

```text
50db73fc799f20a7120a8b5f653b16cc123d856f
```

Он существует в открытом объединённом дереве:

```text
https://github.com/xanderlent/COMBINED_android-kernel-exynos
```

Это публичная комбинированная копия AOSP Exynos для Pixel Watch, **не** исходный Galwear-проект. Никаких коммитов или запросов на запись в неё не выполняется.

`build/r800_aosp_source_probe.sh` читает только этот commit, выполняет sparse checkout файлов, упомянутых в `src/kernel/r800-wearos.patch`, и запускает `git apply --check` через `build/r800_kernel_preflight.py`. Патч не применяется. Проверяются точный HEAD и отсутствие модификаций source tree.

GitHub Actions workflow:

```text
.github/workflows/r800-kernel-source-validation.yml
```

При получении результатов чётко разделяются: наличие SHA, успешный `git apply --check`, компиляция и работоспособность на устройстве. Успех более раннего шага не означает успех последующих.

## Компилятор

Файл `src/kernel/r800.config` требует:

```text
CONFIG_CLANG_VERSION=190104
CONFIG_LLD_VERSION=190104
```

Это соответствует Clang и LLD **19.1.4**. `build/r800_toolchain_inventory.py` формирует отдельный отчёт с обнаруженными версиями и `clang_lld_versions_match_config`. При несоответствии версиям выводится `MISMATCH_OR_UNAVAILABLE`, а не ложный PASS сборки.

Для отдельной пробной компиляции используется Alpine 3.21 с пакетами LLVM 19.1.4. **Изображение контейнера по digest пока не закреплено**, поэтому побайтовая воспроизводимость сборки не доказана.

## Пробная компиляция без релизного initramfs

Выполняется через:

```text
.github/workflows/r800-kernel-compile-smoke.yml
build/r800_kernel_compile_smoke.sh
```

Workflow после проверки точного SHA и `git apply --check` раскрывает полное исходное дерево во **временной копии runner**, применяет патч только там и пытается собрать `Image` с `make -j2`.

Важный дефект исторического рецепта: `r800.config` содержит

```text
CONFIG_INITRAMFS_SOURCE="/root/initramfs/list.txt"
```

Этот файл отсутствует в форке. Поэтому временная конфигурация пробной сборки ставит `CONFIG_INITRAMFS_SOURCE=""`. Исходная `r800.config` **не изменяется**. Получившийся Image нельзя считать загрузочным образом для SM-R800, и workflow никогда не загружает его как артефакт, релиз или прошивку.

Результат считается успешным только при действительном завершении `make ... Image` и наличии ненулевого `arch/arm64/boot/Image`. Неуспешная компиляция — диагностический результат, а не основание менять модель/исходное ядро наугад.

## Оставшиеся шаги к воспроизводимому ядру

1. Добиться успешной компиляции пробного `Image` и устранить конкретные ошибки по CI-логам.
2. Заменить локальный отсутствующий `/root/initramfs/list.txt` документированным, воспроизводимым исходным initramfs (отдельная задача).
3. Закрепить Docker image digest и версии всех дополнительных инструментов.
4. Проверить пакетирование NZIT, Device Tree и signature trailer — без публикации прошивки.
5. Повторить сборку в двух чистых runner и сравнить хеши; различия проанализировать.
6. Только после подтверждённого восстановления часов обсуждать аппаратные испытания.

**Ни один офлайн-результат не подтверждает безопасное прошивание SM-R800.**
