# SM-R800 — независимые эксперименты питания дисплея и ABOX

В предыдущем helper ожидание sys.boot_completed ограничено 120 секундами.
После тайм-аута код продолжал выполнение и безусловно устанавливал
r800_keep_panel_on=0. Также безусловно активировался экспериментальный
r800_rtpm_poweroff и менялся режим runtime PM ABOX.

Теперь:

- PANEL_REALBLANK: отдельный opt-in для реального выключения панели,
  только при sys.boot_completed=1. Без маркера после успешного boot
  сохраняется r800_keep_panel_on=1 (консервативный режим ядра).
- ABOX_POWEROFF: отдельный opt-in после завершения boot. Перед записью
  проверяется исходный режим control; он восстанавливается после
  попытки включения экспериментального параметра.
- При тайм-ауте boot оба новых блока не выполняют записи в sysfs.
  Остальные исторические действия post-boot helper не изменены.
- mkpayload-release.sh исключает PANEL_REALBLANK, ABOX_POWEROFF и
  существующий GPU_SCALE, как и прежние SLEEP/CPUIDLE_DEEP/OVERLAY.

Новые флаги независимы от SLEEP и CPUIDLE_DEEP. Их включение на часах
не рекомендуется до подтверждения аппаратного восстановления.

Сохранение панели включённой может увеличить расход батареи; это
осознанный компромисс для экспериментальной ветки. Параметры ядра,
порядок DECON/DSIM и механизм suspend не изменены. Не доказано,
что чёрный экран либо зависание при выходе из DOZE устранены.
Полная транзакционность ABOX при аварийном завершении helper не
гарантируется: восстановление control является best effort.

Девять тестов проверяют изолированные блоки shell на временных файлах,
не на настоящем sysfs. CI также запускает ранее добавленные power
policy и watchdog тесты. Не считать наличие workflow результатом PASS.

Следующий шаг: подтверждение CI, анализ сохранённых реальных трасс
OFF/DOZE/ON и сравнение потребления при идентичных нагрузках.
Ни один результат этого этапа не является допуском к прошивке.
