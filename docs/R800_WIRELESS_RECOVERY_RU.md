# SM-R800 — восстановление Wi-Fi (NON-RELEASE)

В историческом android-helper.sh обнаружена подстановка sed с байтом
0x01 вместо обратной ссылки на SSID. Исправлено извлечение обычного
quoted SSID; подключение требует непустых SSID и passphrase.
Сложные escaped/hex SSID, WPA3 и enterprise не реализованы.

Резервный режим требует наличие конфигурации и исполняемых файлов,
успешное выключение Android Wi-Fi и статус stopped у wpa_supplicant.
При запуске Android supplicant резервный цикл прекращает работу.
KeepWifi запускается только при MODE=android.
Резервный supplicant и DHCP работают в foreground как дочерние
процессы цикла; повторный запуск только после исчезновения PID.
Это не полноценный supervisor: гонки PID reuse и внешнее включение
Wi-Fi между опросами остаются возможными.
Конфигурация создаётся с umask 077, каталог 0700, файл 0600.
Правила IP routing проверяются на наличие перед добавлением.
Изменения относятся к существующему DEV режиму; обычная политика
Wear OS не изменена. Исторический DEV telnet не является безопасным
удалённым доступом; новых сетевых служб не добавлено.

Девять тестов (три выполнения фактической строки sed, статические
проверки и sh -n). CI настроен, результат ещё не подтверждён.

Kernel patch содержит восстановление SDIO clock после reset.
Драйвер bcmdhd, Bluetooth BCM43012, pairing, реальный throughput
и восстановление после сна не проверены и не изменены.
Следующий шаг — тестирование интерфейсов на уровне сборки и
интеграционная проверка всех накопленных веток.
Main/upstream/PR/реальные часы не затронуты.
