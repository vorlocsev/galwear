# SM-R800 — устранение ложных срабатываний display watchdog

Статический анализ исторического payload/android-helper.sh показал:
- /proc/interrupts читался только по CPU0;
- возраст composer рассчитывался из поля 22 через cut, без корректной
  обработки comm, нескольких PID и отсутствующего /proc/PID/stat;
- CLK_TCK был жёстко задан как 100;
- использовалось настенное время, подверженное коррекции;
- ошибки HWComposer не связывались с конкретным экземпляром процесса.

Новый payload/r800-display-watchdog.sh содержит изолированные функции.
Watchdog суммирует CPU-счётчики одной однозначной строки frame IRQ,
использует uptime, фактический CLK_TCK, PID и starttime. При отсутствии
валидной выборки сбрасывается базовая линия. Событие logcat связывается
с PID и starttime; перед восстановлением повторно проверяются процесс
и IRQ. Неизвестные значения отклоняются. После восстановления нужен
новый сигнал ошибки; прежняя эскалация при повторном запуске composer
более не считается доказанной без новой выборки.

Старый механизм восстановления (включая принудительную перезагрузку
при zero-copy) не является доказанно безопасным. Не запускайте
исторический payload на часах для проверки этого изменения.
Если getconf CLK_TCK, формат logcat или имя IRQ на Android отличаются,
новый watchdog может не срабатывать: это осознанный fail-closed режим,
требующий проверки на реальном журнале. Общий аппаратный dead-man
не менялся.

Графический Kconfig содержит FB, Mali Midgard R28P0 и DMA shared buffer,
DRM выключен; DTS содержит DECON, DSIM и arm,mali. Это не подтверждает
совместимость графического HAL. Исходник composer не удалось получить
по доступным путям; изменение относится к его watchdog, не к GPU HAL.

CI: девять синтетических тестов и sh/BusyBox syntax check. Без запуска
Android helper, без сборки firmware, без реальных часов. Main и
upstream не изменяются.
