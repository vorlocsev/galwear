# SM-R800 — диагностика графических зависаний по сохранённым трассам

Патч ядра содержит изменения DECON/DSIM для сохранения состояния
панели, порядка инициализации, DOZE и эквивалентного pixel clock.
Код HWComposer по доступным путям не найден; реализация zero-copy,
владение DMA-BUF и жизненный цикл fences не проверены.

Новый инструмент читает исключительно заранее сохранённые файлы:

```sh
python3 build/r800_graphics_trace.py \
  --kernel-log /path/to/kernel.log \
  --frame-samples /path/to/frame-counts.txt \
  --output /tmp/r800-graphics-report.json
```

kernel.log: строки dmesg с числовым uptime в квадратных скобках.
frame-counts.txt: два целых числа на строку, uptime в секундах
и суммарный счётчик одного frame IRQ по всем CPU. Например:

```
10 42
13 42
16 42
19 43
```

Использовать трассы одной загрузки, одной шкалы времени. Отчёт
самостоятельно не проверяет это условие. Порог 5 с при шаге не
более 4 с — диагностическая эвристика, не аппаратная спецификация.
Разрыв выборки не считается отсутствием кадров. Сброс счётчика
или обратный ход времени отклоняются. Остановка кадров при
выключенном экране может быть нормальной. Совпадение событий
fence timeout, IOMMU fault и DECON/DSIM timeout по времени
не доказывает причинность.

Девять синтетических тестов и отдельный CI workflow.
Не запускать сборщик на часах для этого этапа; инструмент не
монтирует разделы, не выполняет ioctl, не запускает firmware.
safe_to_flash=false.

Далее: при наличии исходника HWComposer проверить acquire/release
fences, ошибки ioctl, lifetime dma-buf FD и последовательность
present/retire; при наличии реальных трасс проверить переходы
OFF/DOZE/ON и отдельно zero-copy и копирующий путь.
