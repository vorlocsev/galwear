# SM-R800 — восстановление Audio HAL при отказах PCM/HFP

Исправления в src/hal/audio_r800.c, только в форке.

- PCM read/write: нулевой, отрицательный или превышающий запрос результат
  считается отказом. Частичные записи продолжаются с корректного смещения,
  счётчик written учитывает принятые PCM кадры. Остаток задерживается на
  длительность недоставленных кадров; на входе заполняется тишиной.
- Запросы с неполным кадром отклоняются; NULL PCM не разыменовывается.
- HFP: медиа потоки переводятся в standby под блокировками; отказ mixer,
  PCM open/ready/prepare/start прекращает запуск и освобождает ранее
  открытые каналы. Состояние HFP сбрасывается, исходный маршрут
  восстанавливается best effort. Ошибка возвращается вызывающему коду.
- HFP PCM хранятся в экземпляре устройства; флаги mic_mute/hfp_active
  атомарны. Допустимы SCO 8000/16000 и hfp_enable true/false.

Тесты компилируют фактические функции hfp_start/hfp_stop с подставными
PCM и mixer API. Проверяются успешный цикл, отказ открытия, readiness
и запуска на каждом из четырёх каналов, отказ mixer. Два остальных
теста статически проверяют защиты PCM и атомарные флаги.
Это НЕ сборка полного HAL Android NDK и НЕ проверка tinyalsa/драйвера.

Ограничения: фактическая работа DSP, микрофона, динамика и HFP на часах
не проверена. Встроенный DSP-маршрут звонка может обходить программное
mic_mute; атомарность флага сама по себе этого не исправляет.
Ошибки обратного переключения mixer пока не гарантируют восстановление
всех аппаратных регистров. Длительные блокировки tinyalsa/драйвера,
lifetime потоков и полная компиляция Android HAL требуют отдельного
исследования. ABOX firmware retry patch не менялся.

Никаких сборок firmware, прошивок, PR или изменений main/upstream.
