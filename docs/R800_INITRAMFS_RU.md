# SM-R800: изолированный минимальный initramfs (не релиз)

**Ветка:** `development/r800-kernel-source-ci-20261124` в **`vorlocsev/galwear`**. Исходный репозиторий Depth118, `main` и реальные часы не изменяются.

## Почему добавлен новый рецепт

Старый `src/initramfs/build.sh` использует абсолютные пути `/mnt/d/r800`, `~/initramfs` и `~/kernel`. При этом `src/kernel/r800.config` ожидает несуществующий в форке `/root/initramfs/list.txt`.

Новый экспериментальный рецепт не зависит от этих пользовательских путей:

- `build/r800_initramfs_compile_smoke.sh` собирает только существующий `src/initramfs/init.c` под AArch64 при помощи **Clang и LLD 19.1.4**;
- `build/r800_initramfs_spec.py` проверяет, что получился little-endian ELF64 для AArch64 без динамического ELF-интерпретатора и с доступными в файле `PT_LOAD` сегментами;
- тот же скрипт создаёт `initramfs.list` для `gen_init_cpio`: `/dev`, `/dev/console`, `/proc`, `/sys`, `/data`, `/init`;
- в `initramfs-evidence.json` фиксируются размер и SHA-256 бинарника. Сам исполняемый `init` в GitHub Actions **не публикуется**.

Сборка запускается в изолированном контейнере Alpine 3.21. Репозиторий монтируется только для чтения. Пример проверки внутри временного контейнера:

```sh
sh /repo/build/r800_initramfs_compile_smoke.sh \
    /repo /scratch/r800-initramfs
```

Workflow: `.github/workflows/r800-initramfs-smoke.yml`.

## Ограничения

Этот initramfs — минимальный экспериментальный стартовый процесс, **не загрузочный образ и не полноценная Wear OS**. Скрипт не монтирует реальные разделы часов и не запускает firmware installer.

Несмотря на фиксацию версий LLVM, бинарный файл не считается побайтово воспроизводимым до двух независимых сборок и сравнения SHA-256. Список `gen_init_cpio` детерминирован только для одинакового бинарника и одинакового абсолютного пути к нему.

Существующий `init.c` умеет монтировать `/data` из `mmcblk0p17` в режиме записи, если когда-либо запущен на реальном устройстве. Поэтому **данный этап ограничен кросс-компиляцией и офлайн-структурными тестами**. Нельзя считать его безопасным для загрузки на SM-R800.

Перед включением в релиз необходимо отдельно: проверить исходный ELF, подтвердить права/владельцев и формат CPIO, собрать пробный `Image` с встраиванием initramfs в изолированной сборке, проверить скрипты запуска, предусмотреть безопасный read-only режим диагностики, получить подтверждённую схему восстановления загрузчика.

## Тестирование

```sh
python3 -m unittest discover -s tests -p 'test_initramfs_recipe.py' -v
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

В тестах используются только синтетические ELF, временные файлы и локальные процессы. В частности проверяются защита от неверной архитектуры, повреждённых заголовков, динамического интерпретатора, выходящих за границы LOAD-сегментов и символьных ссылок.

**Успешный CI не подтверждает безопасное прошивание часов или возможность загрузки готовой Wear OS.**
