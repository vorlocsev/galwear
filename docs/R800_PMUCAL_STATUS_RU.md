# SM-R800: достоверность статуса PMUCAL (NON-RELEASE)

База ветки: development/r800-pd-rollback-20261125.
База Linux: 50db73fc799f20a7120a8b5f653b16cc123d856f.

## Исправления

- pmucal_local_is_enabled отклоняет отсутствующую или пустую status sequence.
  Код возврата pmucal_rae_handle_seq проверяется до сравнения value/mask.
  Ошибка передаётся вызывающему коду, неожиданный положительный код — -EIO.
- __exynos_pd_power_on/off принимают только 0 и 1 от cal_pd_status;
  неизвестное состояние блокирует переход до вызова power control.
- BCM sync допускается только при статусе 1.
- Probe genpd не считает произвольный отрицательный статус выключенным
  доменом; использует проверенный initial_state для сообщения.
- Ранее добавленные guards системного suspend и отката PD сохранены.

## Проверки

Две изменённые diff-секции проверены по точному исходному SHA с контролем
контекста, количества строк и смещений. Добавлены восемь статических
unittest; соответствующие восемь условий проверены на сохранённом patch.
Запуск Python unittest, полный git apply --check, сборка ядра и CI не подтверждены.

## Ограничения и следующий этап

RAE PMUCAL_READ использует raw MMIO без возвращаемого кода ошибки.
Возврат 0 от RAE не доказывает отсутствие bus fault или аппаратно неверных
данных. Не проверены все вызывающие функции во всём дереве ядра
(поиск кода не вернул результатов), только exynos-pd.c и ранее изменённый
syscore путь. Следующий этап: аудит status sequence Exynos 9110, типов
операций, валидности base_va и условных чтений; затем проверка abort
между syscore и PSCI. Не включать deep sleep; safe_to_flash=false.
Работа только в форке, без PR и изменений main/upstream.
