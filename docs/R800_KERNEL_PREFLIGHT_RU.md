# SM-R800: проверка применимости патча ядра (только форк)

Рабочая ветка: `development/r800-kernel-preflight-20261124` в
`vorlocsev/galwear`. Исходный проект не изменяется. В `main` форка
коммиты не вносятся, PR не создаются, ядро на часы не записывается.

## Обнаруженные проблемы

- Скрипт `build/mk_kernel_patch.sh` ошибочно искал патч по
  `kernel/r800-wearos.patch`; действительный путь —
  `src/kernel/r800-wearos.patch`. Путь исправлен.
- Генератор патча ранее не проверял исходный SHA, теперь он отклоняет
  дерево не на ожидаемом коммите. Неустановленные аргументы также
  приводят к отказу.
- В `build/kbuild-native.sh` и `src/initramfs/build.sh`
  остались абсолютные пути разработчика под `/mnt/d/r800` и `~/kernel`.
  **Полная воспроизводимость сборки пока не достигнута.**

## Текущий базовый коммит ядра

Из `build/mk_kernel_patch.sh`:

```text
50db73fc799f20a7120a8b5f653b16cc123d856f
```

Это значение используется как **пин исходного ядра**, но доступность
и подлинность внешнего дерева исходников пока не проверены. Не
путать этот SHA с коммитами самого форка Galwear.

## Новый `build/r800_kernel_preflight.py`

Полностью локальная операция на чтение, не применяет патч, не выполняет
компиляцию, не подключается к часам и не открывает сеть.

Проверка только содержимого форка:

```sh
python3 build/r800_kernel_preflight.py --report kernel-preflight.json
```

Ожидаемый статус:

```text
STATIC_ONLY_SOURCE_NOT_PROVIDED
```

Выполняются проверки числа и безопасности путей файлов в diff,
обязательных Exynos power/cpuidle изменений, необходимых Kconfig
параметров, наличия `src/dt/r800.dts`, SHA-256 патча/конфигурации/DT
и совпадения пина со скриптом регенерации. На текущем коде патч охватывает
131 файл и 203 hunk.

Проверка на **отдельно подготовленном, чистом** локальном дереве ядра
с исходным коммитом `50db73f...`:

```sh
python3 build/r800_kernel_preflight.py \
  --source-tree /path/to/clean-exynos9110-kernel \
  --report kernel-source-preflight.json
```

Программа сравнивает точный `git rev-parse HEAD`, проверяет чистоту
`git status --porcelain` и выполняет только:

```sh
git apply --check /path/to/galwear/src/kernel/r800-wearos.patch
```

Команда `--check` **не применяет патч**. При несовпадении базового SHA,
изменениях рабочей копии или конфликте любого hunk результат —
`REJECT`; запись образа не производится.

Даже при успешном сравнении статус будет
`PATCH_APPLIES_TO_PINNED_SOURCE_ONLY`, а `kernel_compiled=false` и
`safe_to_flash=false`.

## CI

Workflow `.github/workflows/r800-kernel-preflight.yml` запускает
`sh -n` для скриптов сборки, `git apply --numstat`, структурный
аудит и 16 синтетических тестов на временных Git-репозиториях.
На GitHub Actions из форка **не скачивается** внешнее дерево Exynos.
В артефакте `r800-kernel-static-preflight` сохраняется JSON отчёт.

### Что ещё обязательно сделать для настоящей сборки

1. Подтвердить доступный и юридически пригодный источник Linux 4.19
   Exynos 9110 для точного базового SHA; без него нельзя проверить
   применение patch в настоящем дереве.
2. Организовать **изолированную копию** дерева ядра, не меняя внешний
   Git-репозиторий и пользовательскую рабочую копию.
3. Зафиксировать версии Clang/LLVM, binutils, dtc и флаги компиляции.
4. Запустить чистую `make ... Image` с конфигурацией `r800.config`
   в изолированном GitHub runner и сохранить логи/hash результата.
5. Собрать NZIT только из валидированных входов и проверить структуру.
6. Не разрешать аппаратную установку до испытанного восстановления.

**Предупреждение:** существующий `mk_kernel_patch.sh` при реальной
регенерации использует `git add -N` и `git reset`, поэтому его
нельзя считать полностью read-only. Новый preflight, в отличие от
него, ничего не записывает в дерево исходников.

Зелёный CI подтверждает только синтетическую и статическую проверку,
а не компиляцию ядра и не устранение зависаний suspend/resume.
