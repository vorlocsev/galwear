# SM-R800 — воспроизводимость полного ядра с read-only initramfs

Ветка разработки: `development/r800-kernel-repeatability-20261125` в
**только собственном форке `vorlocsev/galwear`**.

`main`, репозиторий Depth118, PR и физические SM-R800 не затрагиваются.
Выкладываются лишь JSON с хешами, **не** готовые `Image`, CPIO, ELF,
NZIT или устанавливаемые TAR.

## Доказанные предпосылки

- Базовый исходный код Linux 4.19 имеет точный SHA
  `50db73fc799f20a7120a8b5f653b16cc123d856f`.
- Патч Galwear проходит `git apply --check` на этом дереве.
- На этапе CI №45489397653 и №45490134949 собран объединённый
  экспериментальный `Image` и проверено содержание встроенного CPIO,
  **но эти запуски использовали старый /init, который мог монтировать
  /data на запись**.
- Новый `src/initramfs/init-readonly.c` компилируется на двух
  независимых runner, исполняется в QEMU user-mode, его два SHA
  совпадают (CI №45491810953). Код не содержит монтирования
  /data/eMMC или перехода к Wear OS.

## Новая проверка двух полных Image

Workflow:
`.github/workflows/r800-kernel-repeatability.yml`.

При push в ветку запускаются два независимых runner, обозначенные
`a` и `b`, для **одного и того же коммита**:

1. Оба проверяют тесты SHA-манифестов, безопасности read-only /init и
   содержимого CPIO.
2. Оба независимо получают точный источник Exynos 9110, проверяют
   применимость патча и раскрывают временное дерево исходников.
3. Каждый фиксирует реальный Docker image ID `alpine:3.21` и
   устанавливает Clang/LLD **19.1.4**.
4. Каждый компилирует отдельный AArch64 read-only `/init` и
   полное Linux `Image` со встроенным initramfs.
5. CPIO анализируется на байтовое совпадение `/init`, на ожидаемые
   имена, права и идентификатор `/dev/console`.
6. Каждый сохраняет только `r800-image-repeatability.json` с SHA-256
   `Image`, CPIO, ELF, `.config`, patch, фиксированными идентификаторами
   исходников и контейнера.
7. Третий job скачивает два JSON и вызывает
   `r800_reproducibility_audit.py compare`.

Инструмент различает **два job одного GitHub run** по полям
`runner_replica=a|b`, а также ранее поддерживаемые отдельные
run ID/attempt. Сравнение файлов с одним и тем же run и
одинаковой репликой отклоняется как недоказанная независимость.
Третий job дополнительно требует `first_runner_replica=a`,
`second_runner_replica=b` и оба run ID равными ID текущего CI.

## Результат, который имеет доказательную силу

Только после полного PASS всех трёх jobs:

```text
TWO_RUN_HASH_MATCH
two_run_byte_identity_observed=true
general_reproducibility_proven=false
safe_to_flash=false
```

Если различаются SHA `Image`, CPIO, исходный патч, Kconfig,
Docker image ID или любой обязательный параметр, получаем
`REJECT_MISMATCH` с перечнем отличающихся полей. Само сравнение
**не скрывает различия** и не считает совпадение одного `/init`
доказательством идентичности ядра.

Два удачных прогона подтверждают только побайтовое совпадение
**этих двух сборок**. Полная доказанная воспроизводимость потребует
дополнительно фиксации всех пакетов системы, image digest, версий
утилит, входного initramfs и независимого повторения сборки.

## Что всё ещё не сделано

- Аппаратный boot и восстановление на реальном SM-R800.
- Проверка S-Boot signature, anti-rollback и настоящего PIT.
- Работающий стек Wear OS, дисплей, сенсоры и энергосбережение.
- Подготовка безопасного флеш-архива для пользователя.

Ни успешная сборка, ни `TWO_RUN_HASH_MATCH` **не дают разрешения
прошивать устройство**.
