# SM-R800: Linux 4.19 + экспериментальный встроенный initramfs

**Разработка только в форке `vorlocsev/galwear`**, ветка
`development/r800-embedded-initramfs-20261125`. Никаких PR, изменений
`main`, публикации прошивок и аппаратных записей.

## Что подтвердили предыдущие сборки

- `Image` Linux 4.19 Exynos 9110, базовый SHA ядра
  `50db73fc799f20a7120a8b5f653b16cc123d856f`, успешно
  компилируется с Clang/LLD 19.1.4 **с отключённым initramfs**:
  GitHub Actions №45486293020.
- Минимальный экспериментальный `/init` отдельно успешно
  компилируется в AArch64 ELF64 без динамического загрузчика:
  GitHub Actions №45488006818.
- Эти две успешные сборки **не доказывали** работоспособность
  их сочетания и не подразумевали возможность запуска Wear OS.

## Новая объединённая сборка

`.github/workflows/r800-embedded-initramfs-build.yml` выполняет:

1. Тесты конфигурации, ELF и установленных ограничений.
2. Проверку точного исходного commit `50db73f` и
   `git apply --check` без изменений исходников.
3. Полную распаковку исходного дерева в временном runner.
4. В контейнере Alpine 3.21 — компиляцию существующего
   `src/initramfs/init.c` в статический AArch64 `/init`.
5. Генерацию `initramfs.list` с ровно шестью записями
   (`/dev`, `/dev/console`, `/proc`, `/sys`, `/data`, `/init`).
6. `build/r800_embedded_initramfs_config.py` проверяет
   SHA-256, ELF-формат, отчёт предыдущей сборки, отсутствие
   динамического интерпретатора и неразрешённых записей.
7. Только во временном `O=` каталоге изменяется
   `CONFIG_INITRAMFS_SOURCE` на путь к проверенному списку.
   После `make olddefconfig` этот путь снова проверяется.
8. `make -j2 Image`, проверка существования `Image`.
9. `build/r800_cpio_audit.py` анализирует фактически сформированный
   `usr/initramfs_data.cpio` (или `.gz`), проверяет структуру newc,
   ровно шесть ожидаемых записей и полное совпадение SHA-256 файла
   `/init` с заранее проверенным ELF. Незнакомые записи, ссылки,
   дубликаты, усечённый архив и несовпадение содержимого — отказ.

Добавлены отдельные тесты `tests/test_cpio_audit.py` с искусственными
CPIO-архивами, в том числе с ошибками. Даже успешное совпадение
CPIO не доказывает, что ядро загрузится на SM-R800.

Обычный `build/r800_kernel_compile_smoke.sh` сохраняет прежний
режим **без** встроенного initramfs. Новый режим включается только
через `R800_SMOKE_INITRAMFS_LIST`.

Отчёты сохраняются в GitHub Actions в виде **текста и JSON**.
Сам `Image`, `/init`, промежуточные ELF/CPIO и загружаемый
NZIT **не публикуются**.

## Ограничения безопасности

Этот initramfs содержит исходный экспериментальный `init.c`,
который при реальном запуске пытается монтировать `mmcblk0p17`
в режиме записи. **Мы не проверяли его работу на реальных часах**
и не утверждаем, что такой образ безопасен для загрузки.

Пробная сборка не содержит законченной Wear OS, не проходит
Samsung secure boot и не может считаться подписанной или пригодной
для прошивки. Доступность Wireless/USB recovery, соответствие
памяти устройства, Tizen rollback и поведение питания не доказаны.

В более позднем этапе до любых аппаратных испытаний потребуется
отдельный, по умолчанию **read-only** initramfs с отключённой
записью на eMMC, подтверждённые заводские резервные копии,
защита CM/CSA/EFS и проверенный способ восстановления.

## Следующий шаг

После успешного CI: проанализировать структуру встроенного CPIO,
сравнить SHA-256 двух независимых пробных сборок и удалить
недетерминированные метаданные. Затем отдельно проверить Device Tree
и упаковщик NZIT в безопасном offline-режиме.

**Зелёный GitHub Actions подтверждает компиляцию, не загрузку часов.**
