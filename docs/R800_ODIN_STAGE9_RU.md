# Этап 9: Wireless Odin — отказы, PIT, ACK и ресурсы

**Область изменений:** только форк `vorlocsev/galwear`, ветка `development/r800-odin-stage9-20261124`. Никаких новых PR, изменений `main`, сборок прошивки или подключений к настоящим часам.

## Основные изменения

1. Загрузка live PIT вынесена в `receive_live_pit()`. Размер ответа ограничен структурными параметрами PIT; если данные слишком короткие, слишком большие или повреждены, никаких команд записи (102) не отправляется.
2. PIT читается строго по уже использовавшемуся в проекте протоколу: 500 байт на блок, последний запрос — по объявленному остатку. Подтверждение завершения PIT проверяется отдельно; неизвестный ненулевой статус означает отказ.
3. **Повторное подключение, продолжение частично выполненной записи и автоматический повтор команд запрещены.** После обрыва нельзя надёжно определить, какая часть eMMC уже записана.
4. Добавлены тесты с раздробленными TCP-ответами, ошибками подтверждений, отказами рукопожатия, разрывом соединения и неопределённой набивкой последнего PIT-блока.
5. Сокеты сервера и открытые TAR-файлы закрываются при ошибке установки listener, `accept()` и настройки принятого сокета. Для `--reboot-only` ожидание соединения также ограничено.
6. Все прежние проверки remain: обязательное сравнение `sboot.bin` и recovery с reference combination-архивом, проверка структуры NZIT/EXYN, полного состава TAR, live PIT и геометрии разделов.

## Неподтверждённые свойства протокола

- Неизвестно, отдаёт ли реальный wireless Odin последний PIT-блок ровно объявленной длины или всегда 500 байт с дополнением.
- Нельзя утверждать, что `CMD_PIT:3` всегда подтверждает успех нулевым кодом.
- Семантика порядковых номеров подтверждений данных не подтверждена дампом трафика; поэтому новая логика не делает предположений об их последовательности.
- Никакие тесты не доказывают совместимость с retail или engineering S-Boot.

Если настоящий протокол ведёт себя иначе, текущий установщик **откажет в работе**, а не попытается самостоятельно угадать формат.

## Проверка

В GitHub Actions, из корня ветки:

```sh
python3 -m compileall -q installer tests
sh -n payload/android-helper.sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Отдельно тесты этапа:

```sh
python3 -m unittest discover -s tests -p 'test_odin_stage9.py' -v
```

Все входные данные тестов синтетические; нет физических часов, сетевого подключения, реального дампа PIT или записи eMMC.
