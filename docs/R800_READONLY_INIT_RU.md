# SM-R800 — безопасный тестовый /init без записи в eMMC

Область изменений: исключительно форк `vorlocsev/galwear`, ветка
`development/r800-readonly-init-20261125`. Ни исходный репозиторий
Depth118, ни `main` форка, ни реальные часы не затрагиваются.

## Причина изменения

Старый `src/initramfs/init.c` при запуске использует
`/dev/mmcblk0p17`, монтирует `/data` **на запись**, обращается к
framebuffer и пытается запустить `/data/r800dev/start.sh`.
Его успешная кросс-компиляция не делала такой сценарий безопасным
для аппаратного тестирования.

Чтобы отделить проверку связки `Image` + встроенный initramfs от
изменений постоянных данных часов, добавлен
`src/initramfs/init-readonly.c`.

## Новая программа `/init`

- Использует только два системных вызова AArch64: `write` (#64)
  в **уже открытый** stdout и `nanosleep` (#101).
- Выводит фиксированное сообщение без реальных идентификаторов
  устройства, затем спит с интервалами 5 секунд.
- Не открывает устройства, не обращается к eMMC, не монтирует
  файловые системы, не меняет питание и не запускает Wear OS.
- Не делает вызовов управления framebuffer, сетью или оборудованием.

Это **отдельный диагностический заглушечный PID1**, а не
самодостаточная Wear OS, не проверенный путь восстановления и не
готовый загрузочный образ. На реальных часах он НЕ проверялся.

## Сборка и проверка

`build/r800_initramfs_compile_smoke.sh` теперь использует
`src/initramfs/init-readonly.c` по умолчанию. Старый `init.c`
остаётся в проекте для документирования исторического состояния,
но не используется этим тестовым рецептом.

Проверки:

```sh
python3 -m unittest discover -s tests -p 'test_readonly_init.py' -v
python3 -m unittest discover -s tests -p 'test_initramfs_recipe.py' -v
sh -n build/r800_initramfs_compile_smoke.sh
```

`.github/workflows/r800-init-repeatability.yml` на двух
независимых GitHub runners компилирует именно read-only `/init`,
сравнивает SHA-256 и размеры бинарников, исходный SHA,
версии Clang/LLD 19.1.4 и Docker image ID. CI сохраняет только
JSON с хешами, но не ELF и не firmware.

Статические тесты проверяют два разрешённых номера системных вызовов
и отсутствие известных опасных обращений. Они **не являются
формальной верификацией всей исполняемой программы**.

## Что остаётся заблокированным

1. Завершение полной экспериментальной сборки `Image` со
   встроенным read-only initramfs на той же ветке.
2. Отдельная проверка встроенного CPIO с побайтовым SHA-256 `/init`.
3. Воспроизводимость целого `Image` на двух независимых runners,
   закреплённых по точному Docker image ID и исходному SHA.
4. Настоящий boot на SM-R800: не разрешён этим этапом, отсутствует
   подтверждённый аппаратный способ восстановления, риск проверки
   подписей S-Boot и anti-rollback остаётся.
5. Для разработки полноценного Wear OS init потребуется отдельная,
   аудируемая последовательность и политики доступа к разделам.
   Этот minimal smoke init намеренно **ничего не запускает**.

**CI PASS подтверждает только подготовку/компиляцию тестового ELF,
не безопасность загрузки и не готовность прошивки.**
